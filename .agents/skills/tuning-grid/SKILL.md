# 조율 격자

값을 하나씩 바꿔가며 "이게 나은가?"를 반복하지 않는다. 그러면 앞 것을
기억하지 못해서 결국 마지막 것을 고르게 된다.

**변수 하나를 N칸으로 뽑아 한 장에 나란히 놓고 고른다.**

메타볼 획 두께를 이렇게 정했다(4단×3단 = 12칸 한 장). 0.3em은 글자가 윤곽
밖으로 삐져나오고 0.9em은 다시 둥근 사각형이 되는 것이 **한눈에** 보였다.
값을 하나씩 봤으면 못 봤을 것이다.

## 절차

**1. 축을 하나로 줄인다.** 두 축이면 격자, 세 축이면 이미 실패다. 무엇이
궁금한지부터 정한다.

**2. 스크래치패드에 정적 HTML을 만든다.** 앱을 고치지 않는다. 효과만 떼어내
같은 CSS·같은 글자로 N칸을 그린다. 실제 앱과 같은 서체·배경을 써야 한다 —
검은 배경에서 고른 값이 흰 배경에서 다르게 보인다.

각 칸에 **무슨 값인지 라벨을 박는다.** 라벨 없는 격자는 나중에 쓸모가 없다.

**3. 한 장으로 찍는다.**

```js
import { open } from './scripts/lib/drive.mjs';
const { page, close } = await open({ size: { width: 1200, height: 1400 }, scale: 2 });
await page.goto('file:///' + SCRATCH + '/tune.html', { waitUntil: 'load' });
await page.waitForTimeout(600);
await page.screenshot({ path: `${SCRATCH}/tune.png`, fullPage: true });
```

**4. 움직이는 값이면 정지 화면으로 못 고른다.** 두 시점을 찍어 픽셀 차이를
세고, 수치를 라벨 옆에 적는다.

```python
from PIL import Image, ImageChops
d = ImageChops.difference(Image.open(a).convert('L'), Image.open(b).convert('L'))
moved = sum(d.histogram()[31:])
print(f'{moved/(w*h)*100:.2f}% 움직임')
```

파동을 이렇게 골랐다 — 0.05는 1.63%, 0.12는 3.30%, 0.22는 5.04%. 그런데
**수치만으로 고르지 않았다.** 0.22가 제일 많이 움직였지만 가장자리가 찢어진
종이처럼 보여서 버렸다. 수치는 후보를 좁히고, 마지막은 눈이 고른다.

**5. 고른 값과 버린 이유를 코드 주석에 남긴다.** 상수 옆에 왜 그 값인지,
양옆이 왜 안 되는지 적는다. 그래야 다음 사람이 다시 격자를 짜지 않는다.

```
/** 획을 살찌우는 두께. 얇으면 글자가 윤곽 밖으로 삐져나오고(0.3em),
    두꺼우면 다시 둥근 사각형으로 부풀어 오른다(0.9em). */
export const STROKE_EM = 0.5;
```

## 흔한 함정

- **비율로 안 잡으면 크기가 바뀔 때 깨진다.** 번짐 반경은 px인데 글자는 폰에서
  13px, 벽에서 180px이다. 고정값을 두면 한쪽에서 반드시 틀린다. 잡음 주파수도
  px의 역수라 같은 문제를 갖는다 — 실제로 이걸 놓쳐서 한 번 다시 했다.
- **격자가 실제 맥락과 다르면 잘못 고른다.** 배경색·서체·글자 크기를 앱과
  맞춘다.
- **칸을 너무 많이 만들지 않는다.** 12칸이 한계다. 그 이상은 비교가 안 된다.
