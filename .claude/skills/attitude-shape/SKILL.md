# 태도 → 형상

돌(차분한)을 이 순서로 만들었다(2026-09-27). 다른 형상도 **같은 길을 밟는다.**
무엇이 좋은 형상인지의 기준은 [design/landscape.md](../../../design/landscape.md)에
있다 — 짝(돌 · 별 · 꽃 · 나비), 가져오는 행동, 끝의 기준, 하지 말 것. **먼저 읽는다.**
형상별로 이미 정한 것은 그 문서의 '형상별로 정한 것'에 있다.

## 모든 단계에서 지키는 것

- **절대원칙이 위다.** 형상은 참여자가 고른 태도가 정한다. 시스템이 태도·색·말투를
  대신 고르게 되면 멈춘다
- **새 색을 만들지 않는다.** 칠은 참여자가 고른 색 하나. 선 · 빗금 · 틈은 칠을
  **오려 내서**(mask) 바탕이 비치게 한다 — R13 · R16에서 버린 선과 같다
- **글자에 손대지 않는다.** 테두리 · 그림자 · 기울임을 글자에 덧대지 않는다.
  서체 · 자간 · 크기는 디자이너 몫
- **글이 먼저다.** 모든 형상은 글 + 사방 여백(`cloud.ts`의 `PAD`)을 품는다
- **같은 글은 언제나 같은 형상.** 무작위의 씨앗은 글이다
- **한 글자부터 60자 다섯 줄까지** 무너지지 않는다
- **검정 한 색으로 칠해도 태도가 구별된다** — 색으로 가르지 않는다
- 격자는 **12칸 한 장**, 칸마다 값 라벨. 시안은 스크래치패드에서 — **8단계 전까지
  앱을 고치지 않는다**
- 격자를 만들면 **바로 연다**(`code -r "<경로>"`). 경로만 알려 주지 않는다
- ⏸ 표시는 **멈추고 고르게 하는 곳**이다. 화면에 보이는 결과가 바뀌었으니 다음
  단계로 알아서 넘어가지 않는다

## 단계

**1. 계열을 넓게 ⏸** — 한 형상의 결을 네 계열로 나눠 계열마다 3안(4줄 × 3칸).
흰 칠 · 검은 바탕 · 그 성격의 서체 · 견본 글(`drive.mjs`의 `SAMPLE_TEXT`). 돌은
둥근 돌 / 모서리를 굴린 각 / 날 선 각 / 면이 보이게 깎은 돌이었고 **날 선 각**을
골랐다. 레퍼런스 사진이 있으면 그 비율을 재서 맞춘다(당당한의 폭발형은 캡처의 호
깊이 = 폭의 1/3을 쟀다). 비교는 **흑백을 뒤집어 같은 조건으로** 본다

**2. 규칙으로** — 고른 계열을 '글이 씨앗인 비정형'으로 만든다. 무엇을 몇에서
몇까지 흔드는지(돌: 꼭짓점 6~8, 자리 ±45%, 거리 ±15%)를 정하고 **서로 다른 글
셋**(1줄 · 2줄 · 4줄)에 같은 규칙을 입혀 본다

**3. 긴 글 ⏸** — 네다섯 줄의 글 덩어리는 네모라 형상이 네모로 끌려간다. 지금 규칙
+ 대안 셋 × 2 · 4 · 5줄, 칸마다 **넓이(u²)** 를 적는다. 돌은 줄 수 비례로 흔들기
(돌이 34% 커짐) / 줄 따라 깎기 / 기울이고 두 모서리 깨기 중 마지막(C3). 약해 보이는
안은 **세게 한 판을 다시** 보여 준다 — 첫 C는 기울기가 ±2°뿐이라 안 보였다

**4. 가장자리 ⏸ ×3** — 테두리와 같은 결(선 · 틈 · 빗금)로 방식 넷 × 글 셋 →
고른 방식 안에서 12안(촘촘함 · 깊이 · 방향 · 모양) → **양**(둘레의 몇 %)을 숫자로
비교. 돌은 안쪽 빗금 → 사선 ／ → 범위 넓힘 + 끝까지 + 깊이 0.6u(H3). 깊이는 여백
0.7u가 상한이다 — 넘으면 글자 밑으로 들어간다

**5. 200개로 잰다** — 한 자 ~ 60자 무작위 글(음절 + 띄어쓰기 15%)로 불변식을 센다:
빠진 것 0, 글 + 여백을 못 품은 것 0, 양 · 넓이의 최소 · 가운데 · 최대, 줄 수별 가운데.
한 번이라도 깨지면 규칙을 고친다. 재 봐서 0이어도 **'늘 있다'를 운에 맡기지 않는다**
— 대체 규칙을 코드에 둔다(돌: 빗금 줄기가 없으면 45°에 가장 가까운 변)

**6. 적는다** — landscape.md '형상별로 정한 것'에: 고른 것, **버린 것과 이유**, 잰
결과. 값은 코드에 들어가면 코드가 맞다 — 문서엔 이유를 믿게 둔다

**7. 앱에 넣는다(계획 먼저, 승인 후)** — 자리는 `src/lib/cloud.ts`(Persona에 매개변수
한 벌, `○○For` 함수, `Cloud`에 결과), 그리기는 `src/components/CloudBubble.tsx`.
나머지 성격은 건드리지 않는다. 확인: `npx tsc --noEmit` · `npm run build` ·
`node scripts/audit-a11y.mjs`(위반 0) · 폰 390의 4/5 · 5/5와 벽 1920×1080을 **열어서**
본다(`peek`). `e2e-dock.mjs`는 **묻고** 돌린다 — 규칙 재배포 전엔 테스트 글이 벽에 남는다.
배포하면 벽에 이미 있는 그 성격의 글도 곧바로 바뀐다 — 미리 말한다

**8. 벽의 몸짓 ⏸** — landscape.md의 행동을 `src/admin/WallSimulation.tsx`에. 먼저
**어디에 머무는지** 묻는다(돌: 바닥에 내려앉는다). 0.25초마다 12초 동안 위치 · 간격 ·
기울기를 기록해 수치로 확인하고, 세 장면(떨어지는 중 · 자리 잡음 · 가만히)을 한 장으로
모아 연다. 부딪힘은 **실제 윤곽**(볼록 껍질, 분리축)으로 친다

## 격자 만드는 법

개발 서버(`npm run dev`)를 띄운 채, 스크래치패드의 `.mjs`에서 앱의 모듈을 **그대로
빌려** 그린다 — 글 상자 크기가 실제 앱과 같아야 격자가 거짓말을 안 한다.

```js
import { pathToFileURL } from 'node:url';
import { resolve } from 'node:path';
const { open, SAMPLE_TEXT } = await import(pathToFileURL(resolve(process.cwd(), 'scripts/lib/drive.mjs')).href);
const { page, close } = await open({ size: { width: 1480, height: 1000 }, scale: 1 });   // 확대해 볼 땐 scale: 2
await page.goto(`${page.__base}/?mock=1`, { waitUntil: 'load' });
await page.evaluate(async () => {
  const { cloudForTone, PAD } = await import('/src/lib/cloud.ts');      // Vite가 바로 번역해 준다
  const { foldLines } = await import('/src/lib/fit.ts');
  const { fontMap, formFor, opticalFix } = await import('/src/lib/palettes.ts');
  const lines = foldLines(TEXT);
  const { w: TW, h: TH } = cloudForTone(lines, { font, speed: 0.5, weight: 0.5, manner: 0 }).text;  // 글 상자(u)
  // 형상은 글 상자 왼쪽 위를 원점으로 u 단위로 짓고, viewBox를 그 테두리에 맞춘다.
  // 글은 div 하나: fontFamily = fontMap[font], fontSize = U × opticalFix[font].scale,
  // lineHeight 1.5, transform = scale(formFor(...).scaleX, scaleY), variation · letterSpacing도 formFor에서
  document.body.innerHTML = '';   // 앱 화면을 비우고 격자를 그린다. body엔 display:block을 준다
});
await page.waitForTimeout(3000);   // Adobe 킷은 글자마다 늦게 온다 — 일찍 찍으면 굵기가 섞여 찍힌다
await page.screenshot({ path: `${SCR}/grid.png`, fullPage: true });
```

- 씨앗: 글의 FNV 해시 → mulberry32. 같은 글이면 같은 형상
- 품기: 글 + PAD 네모의 둘레 점들이 **다 안에 들 때까지** 가운데에서 2%씩 키운다
- 빗금: 세로 줄 하나짜리 `<pattern patternTransform="rotate(45)">`을 **마스크 안에서
  검정으로** 칠하면 오려진다
- 부드러운 합집합(꽃 · 나비 · 구름): 번짐 + 알파 문턱 필터(`CloudBubble`의 그 값)
- 앱을 안 거치는 계산(200개 측정)도 같은 페이지에서 모듈을 불러 돌린다
- **칸마다 '벽에서 글 크기'를 적는다.** 벽은 형상 전체를 한 칸에 맞춰 줄이므로 형상의
  긴 쪽이 길수록 글이 작아진다 — 같은 글의 기준 형상 대비 %(= 기준의 긴 쪽 ÷ 이 형상의
  긴 쪽). 넓이 배수만으로는 이 대가가 안 보인다
- **움직이는 것(깜빡임 · 흔들림)은 움직이는 페이지로 고르게 한다.** 형상과 글은 앱 모듈로
  그린 PNG(`locator(...).screenshot`)를 data URL로 깔고, 움직이는 것만 그 위 SVG + CSS
  애니메이션으로. 파일은 스크래치패드, 여는 것은 `Start-Process "<html>"`(브라우저). 내 확인은
  같은 페이지의 정지판 PNG와 `getComputedStyle(...).opacity`를 몇 번 재서 한다
- 시간 값은 토큰(`--t-hold` · `--t-slow` · `--t-return`)과 그 합만 쓴다. 칸 라벨에 토큰 이름을
  적는다. 토큰으로 안 되는 값이 필요하면 묻는다

## 돌 · 별에서 걸렸던 것

- **방향을 잘못 읽었다.** 호(SVG arc)의 방향을 한 번 뒤집었다가 처음 판이 맞았다.
  같은 조건(흑백 반전 · 확대)으로 레퍼런스와 나란히 놓고 읽는다
- **모서리를 파먹었다.** 네모 틀 모서리 양옆의 호가 겹쳤다 → 모서리 끝을 대각선
  바깥으로 밀고, 모서리에 붙은 호만 얕게
- **알로 찍기(R15)는 간격 0.6u에서 형상의 특징을 먹었다.** 별의 끝 · 돌의 모서리
- **가벼운 말이 돌을 떠받쳤다.** 말은 자리를 비키기만 한다 — 돌 밑에 끼면 옆으로
  빠져나간다
- **얹혀 누르는 힘을 충격으로 셌다.** 받침 돌이 내내 기울었다 → 흔들림은 쿵 부딪힐
  때만(빠르기 문턱)
- **상자로 치면 '보이지 않는 경계'가 생긴다.** 기울고 깨진 형상은 상자의 모서리가
  비어 있다 → 실제 윤곽으로, 틈은 3px 안팎
- **이미 있는 파일을 덮어썼다.** 새 문서 이름(`direction-v1.md`)이 5월 문서였다 —
  쓰기 전에 이름이 있는지 본다
- **(별) 끝의 수를 글과 상관없이 고정했다.** 긴 글은 끝이 성기고 짧은 글은 촘촘해졌다 →
  간격을 둘레에 맞추고, 기준은 **고른 견본에서 실제로 잰 둘레**로(어림한 둘레로 맞췄다가
  끝 수가 달라졌다)
- **(별) 걱정한 쪽이 아니라 반대쪽이 깨졌다.** 끝이 적은 형상은 긴 글보다 **짧은 한 마디**
  에서 무너졌다(끝이 작은 별을 압도). 한 줄 · 세 줄 · 다섯 줄을 늘 같이 본다
- **(별) 레퍼런스를 따라가다 대가를 늦게 봤다.** 가늘고 긴 끝은 별을 키워 벽의 글을
  71%까지 줄였다 → 격자에 글 크기를 적고 나서야 고를 수 있었다
- **(별) '가장 가까운 k개'는 작은 형상에서 반대쪽까지 끌어온다.** 방향으로 거르고, 모자라면
  수를 줄인다(자리를 지킨다)
- **(별) 흔들림이 약하면 칸마다 똑같아 보인다.** ±25%는 안 보였다 — 격자에선 눈에 띄는
  폭부터 보여 주고 좁힌다
- **(별) 출발선이 들쭉하면 선 장식이 흩어진 조각으로 보인다.** 선의 자리는 형상의 구조
  (끝 · 골 · 둘러싼 테두리)에 매어야 규칙으로 읽힌다
