# 참조 계약에서 무엇을 가져왔고 무엇을 버렸나

> 2026-09-07. 대상: [DESIGN.md](../DESIGN.md) (토스 근거 기반 재구성, Core v2)
> 검증: `npx oh-my-design-cli@latest design-md validate DESIGN.md` → **valid**
>
> 저 문서가 스스로 요구한 절차다 — "채택 전에 변경을 기록하고 검토하고 검증한다."
> 이 파일이 그 기록이다.

## 0. 검증기가 먼저 막았다

처음 돌렸을 때 `valid: false`였고, 이유가 둘이었다.

```
portable-core missing-product-surface-scope
portable-core missing-primary-task
```

계약이 **어느 표면을 다스리는지**와 **핵심 과업이 무엇인지**를 선언하기
전에는 채택할 수 없다는 뜻이다. 그 둘은 토스가 아니라 이 프로젝트에 관한
사실이므로 코드에서 읽어 채웠다.

- `claim scope kind=product-surface` — **참여자 폰 앱(00~08)뿐**.
  `/wall`(2.4 × 1.5 m, 3~15 m 거리)과 `/admin`은 계약 밖이다. 벽은 UI가
  아니라 작품이고, 폰용 활자·간격 사다리가 거기 그대로 옮겨가지 않는다.
- `claim primary-tasks kind=user-outcomes count=5` — 쓴다 · 말투를 고른다 ·
  꽂는다 · 벽에서 읽는다 · 폰을 뺀다.

> 도중에 한 번 더 막혔다: 파이썬이 파일을 CRLF로 저장하는 바람에
> "Every Core v2 H2 must immediately follow its stable section anchor"가
> 떴다. **이 문서는 LF로 저장해야 한다.**

## 1. 가져온 것

### 활자 — 여섯 역할

문서가 계산값으로 확인한 표를 **수치 그대로** 옮겼다. 행간은 여섯 역할
모두 정확히 1.5다(36/54, 30/45, 24/36, 22/33, 16/24, 14/21).

| 역할 | 크기/굵기 | 쓰는 곳 |
|:--|:--|:--|
| H1 | 36 / 700 | 홈 헤드라인 · 07 · 08 |
| H2 | 30 / 600 | 05 · 06 제목 |
| H3 | 24 / 600 | 02 제목 · 07 카운트 |
| H4 | 22 / 600 | 소개 슬라이드 · 스플래시 · 말투 카드 이름 |
| 본문 | 16 / 400 | 대부분의 문장 |
| 작은 본문 | 14 / 400 | 보조 설명 |

**그전에는 크기가 열아홉 가지였다.** 27·33·42·19·14.5·13.5 같은 값이
섞여 있었고, 그래서 어떤 문장이 어떤 문장보다 중요한지가 화면마다 달랐다.

자간은 **지어내지 않았다.** 저 문서가 자간을 말하지 않으므로 쓰던 값을
그대로 뒀다("미확정을 그럴듯한 기본값으로 대체하지 않는다").

### 버튼 — 높이와 라운드를 한 짝으로

문서가 크기별로 높이와 라운드를 묶어 둔 것이 요점이다. 따로 고르지 않는다.

```
xlarge  56 / 16   기본 액션, 홈 CTA
large   48 / 14   보조 버튼, 축 버튼, 색 바꾸기, 세그먼트 그룹
small   32 /  8   다시 보기
```

좌우 여백 `0 20px`, 라벨 `17 / 600` 도 문서값 그대로다.

### 간격 — 관측 군집

문서가 관측한 군집은 4 · 6 · 8 · 16 · 24 · 32다. 화면 좌우 여백은 24로
잡았다. **그전에는 간격이 열네 가지였다** (3·6·9·10·12·14·18·20·26…).

### 상태 계약

문서는 버튼의 상태를 fill/weak · 시맨틱 색 · **loading · disabled ·
pressed · 키보드 포커스**로 못박는다. 우리에게 **pressed가 없었다.**
지금은 모든 버튼이 눌린 상태를 갖는다.

`loading`은 해당 사항이 없다 — 이 앱에는 제자리 로딩 버튼이 없고
05가 화면 전체를 쓴다. 없는 것을 지어내지 않았다.

## 2. 버린 것

| 문서에 있는 것 | 왜 안 가져왔나 |
|:--|:--|
| 파랑 `#3182f6` | 이 앱의 크롬은 흑백이고 색은 **사용자가 만든 말에만** 산다. 저장소 사실이 참조보다 위다(적용 우선순위 2 > 4) |
| Toss Product Sans | 재배포 권리가 주장되지 않는다. 이미 Pretendard를 쓰고 있다 |
| 그림자·입면 | 문서 스스로 "이번 판에서는 정식 그림자 토큰을 승격하지 않는다"고 한다 |
| 모션 토큰 | 같은 이유로 승격되지 않았다. 04 시뮬레이션의 오버슈트는 크롬이 아니라 **내용**이라 그대로 둔다 |
| 브레이크포인트 | "보편 브레이크포인트를 확립하지 않는다"고 명시한다 |
| 마케팅 버튼(40/46px, 7px 라운드) | 문서가 제품/마케팅을 섞지 말라고 못박는다. 이 앱은 제품 쪽이다 |
| 금융 도메인 패턴 | 계약의 권위 조항: "관련 없는 대상 프로젝트의 권위가 아니다" |

### 라운드는 예외적으로 **가져왔다**

`app.css`에는 '라운드 없음' 원칙이 적혀 있었다. 참조가 라운드를 버튼 계약의
일부로 묶어 두었고, **사용자가 사다리대로 도입하기로 정했다.** 적용
우선순위 1번(명시적 지침)이 2번(저장소 사실)보다 위다. 원칙 주석을
고쳐 이 변경을 기록했다.

한 곳은 여전히 각지다: **벽 미리보기 액자**(`.proj-frame`, `.sim-frame`).
실제 디스플레이가 직사각형이라, 둥글리면 물리적 사실을 잘못 말하게 된다.

## 3. 우리 확장 — 문서에 없어서 지어낸 것

문서의 지침대로 "확장이라고 표시"한다.

| 확장 | 이유 |
|:--|:--|
| 캡션 12 / 11px | 문서의 활자 표는 14px에서 끝난다. 라벨·수치·캡션 자리가 이 앱에는 필요하다 |
| 간격 12px | 관측 군집에 없다. 문서 스스로 "모든 토큰의 증거는 아니다"라고 해서 한 칸 보탰다 |
| `--ink-press` #333 · `--press-tint` 8% | pressed를 흑백으로 옮긴 값. 원본은 파랑 위의 검정 26%다 |
| 단계 진행 레일 | 문서에 진행 컴포넌트가 없다. 상단 바의 구분선을 그대로 막대로 썼다 |
| 32px 버튼의 넓힌 타격 범위 | 문서는 접근성 최소치를 말하지 않는다. 보이는 상자는 문서의 small 그대로 두고 `::after`로 48까지 넓혔다 |

## 4. 위계가 실제로 바뀐 곳

**기본 버튼 아래에 아무것도 두지 않는다.** 그전에는 02·03·04에서 점 세
개와 단계 이름이 버튼 *아래* 있었다. 참조 계약에서 xlarge 버튼은 화면의
마지막 요소다. 진행 표시를 위로 올려, 상단 바의 구분선이 그대로 진행
막대가 되게 했다 — 줄 하나가 두 가지 일을 한다.

상단 바는 44 → **56px**. 상단 바가 이미 "1 / 3 · 말투"라고 말하므로
레일에는 글자를 두지 않았다.

## 5. 검증

| 항목 | 결과 |
|:--|:--|
| `design-md validate` | **valid**, 오류 0 |
| 접근성 (axe, WCAG 2.0/2.1 A·AA) | 10개 화면 **위반 0** |
| 화면 넘침 | 16개 캡처 전부 없음 |
| 폰 ↔ 벽 왕복 | 4항목 통과 |

접근성에서 넷이 걸렸고 전부 고쳤다. 그중 하나가 배울 만하다 —
말투 화면의 옅은 견본에 `aria-hidden`을 걸어도 대비 위반이 남았다.
**대비 규칙의 기준은 낭독기가 아니라 눈이다.** 화면에 보이는 글자면
흐려도 읽을 수 있어야 한다. `--line`(1.4:1)에서 `--muted`(4.5:1)로 올렸다.
